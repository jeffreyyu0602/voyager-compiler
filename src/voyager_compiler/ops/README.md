# ATen Operator Twins in `quantized_ops`

Some operators in this package are **twins** of ATen operators: they perform
the same logical computation by delegating to the corresponding ATen operator,
but expose a different `node.target`.

The distinct target encodes a contract that the ATen target cannot represent.
This keeps transformed graphs correct and eagerly executable without global
monkey-patching.

## Twin Families

| Family | Contract encoded | Defined in |
| --- | --- | --- |
| **Hardware-layout twins** | Nonstandard tensor layouts | [`layout.py`](./layout.py) |
| **Scratch-aware reduction twins** | Backend-owned scratch regions and, for `layer_norm`, padding behavior | [`quantized.py`](./quantized.py) |

### Hardware-Layout Twins

The twins generated by `layout.py` keep the same operator name and schema as
their ATen counterparts:

- `conv2d`, `max_pool2d`, `avg_pool2d`, `adaptive_avg_pool2d`, and
  `_adaptive_avg_pool2d` consume NHWC activations. Convolution weights use HWIO
  when `groups == 1`; grouped and depthwise weights remain unchanged.
- `linear` and `matmul` consume a second operand whose final two dimensions are
  swapped.

The data-layout pass retargets only nodes that operate on tensors placed in a
nonstandard layout. The target therefore records the layout contract carried
by that node.

### Scratch-Aware Reduction Twins

The reduction twins add optional scratch operands that name the on-chip regions
the backend preserves between passes:

| Operator | Scratch regions |
| --- | --- |
| `softmax` | `max`, `sum` |
| `layer_norm` | `mean`, `variance`, `normalized` |

The standard pointwise and untiled bufferization paths supply these operands by
keyword. The reduction node receives them, but its eager implementation ignores
their values and no later FX node reads them. Their presence tells the backend
which regions it owns and may write.

[`reduction_scratch`](../codegen/node_info.py) determines each region's shape
and dtype. The `_REDUCTION_SCRATCH` table maps each accepted source target to
its `quantized_ops` twin and scratch metadata; `reduction_op` returns the mapped
twin.

`layer_norm` is also padding-aware. When its final normalized dimension is
padded, the twin normalizes only the original extent and pads the result back
to the input shape. Although its scratch operands are numerically inert, the
twin's behavior on padded inputs therefore differs from ATen.

## Why Target Coverage Matters

Depending on the pipeline stage, an operator appears under either its ATen
target or its twin target. A lookup keyed by `node.target` sees only the form
present at that stage.

| Contract | What can happen when a lookup misses the twin |
| --- | --- |
| Layout or padding | The graph often fails because shapes or layouts no longer agree. Equal-sized dimensions can still hide the mistake and produce incorrect values. |
| Scratch only | Shapes and numerical results remain valid, so a fallback branch can return a plausible but incorrect estimate without raising an error. |

Risky patterns include dictionary `.get()` calls with defaults, list-membership
checks, and `elif` chains. Scratch-only retargeting is especially easy to miss
because eager execution cannot reveal the omission.

### Worked Example: `OP_PASSES`

[`OP_PASSES`](../codegen/transform/tiling/cost.py) previously listed only the
ATen targets. At the start of standard bufferization, tile search inspected an
unpadded reduction's incoming ATen target and charged `softmax` for three passes
and `layer_norm` for four. The builder subsequently traced the reduction under
its twin target. The reporting estimator inspected that kernel, missed the
twin, and fell back to the one-pass default.

The report therefore understated the reductions' cost—and the corresponding
latency—while still producing plausible numbers. `OP_PASSES` now lists both
ATen and twin targets for each operator.

## Target Lifecycle

Two transformations introduce scratch-aware targets: vector padding can
retarget `layer_norm`, while standard bufferization retargets both `layer_norm`
and `softmax`.

| Path | Created by | Scope and effect |
| --- | --- | --- |
| **Padding** | `_pad_layer_norm` in [`padding.py`](../codegen/transform/padding.py), when the normalized dimension needs padding | Rewrites the node in the main graph. The padded `layer_norm` remains a twin through tiling, fusion, subgraph outlining, bufferization, and reporting. |
| **Bufferization** | `reduction_op` in [`node_info.py`](../codegen/node_info.py) | Retargets batched reductions on the standard pointwise and untiled paths so their traced kernels name their scratch regions. |

For a bare reduction, the bufferizer calls the target returned by
`reduction_op` directly. For a fused `call_module`, `_naming_scratch` in
[`pipeline.py`](../codegen/transform/bufferize/pipeline.py) first calls
`copy_graph_module`, then retargets the reduction and adds one placeholder per
scratch region. The original submodule in the outer node's
`meta['submodule']` is never mutated.

This explains why `_REDUCTION_SCRATCH` contains entries for both
`aten.layer_norm.default` and `quantized_ops.layer_norm.default`: an unpadded
`layer_norm` arrives as ATen, while a padded one is already a twin. Both still
need named scratch regions. `softmax` normally remains ATen until
bufferization.

In the standard pipeline, the targets evolve as follows:

| Pipeline stage | `softmax` | Unpadded `layer_norm` | `layer_norm` requiring padding |
| --- | --- | --- | --- |
| Before vector padding | ATen | ATen | ATen |
| After vector padding, before bufferization | ATen | ATen | Twin |
| Inside a standard traced kernel | Twin | Twin | Twin |

> **Specialized bufferizers must preserve this contract explicitly.** For
> example, [`quantize_mx_outlier.py`](../codegen/transform/bufferize/quantize_mx_outlier.py)
> invokes a fused prefix directly rather than through `_naming_scratch`. A
> reduction in that prefix therefore retains its incoming target and receives
> no scratch placeholders. An already padded `layer_norm` remains a twin but
> still lacks named scratch operands.

## Audit of `node.target` Lookups

The handling labels below mean:

- **Explicit**: the lookup directly lists every reachable twin.
- **Indirect**: another audited lookup provides the coverage.
- **Phase-safe**: the twin is intentionally absent because the standard
  pipeline cannot deliver it to this site. Re-audit this assumption whenever
  pipeline ordering or a specialized path changes.
- **ATen-only by design**: matching an existing twin would be incorrect.

| Site | Operator(s) | Handling | Reason |
| --- | --- | --- | --- |
| [`OP_PASSES`](../codegen/transform/tiling/cost.py) | `softmax`, `layer_norm` | **Explicit** | Lists both ATen and twin targets. |
| [`op_utilization`](../codegen/reporting/cost.py) | `softmax`, `layer_norm` | **Indirect** | Delegates its vector branch to `vector_op_utilization`, which reads `OP_PASSES`. |
| [`_fuse_dequantize_recursive`](../codegen/transform/operator_fusion.py) endpoints | `softmax`, `layer_norm` | `layer_norm`: **Explicit**; `softmax`: **Phase-safe** | Lists the `layer_norm` twin; `softmax` remains ATen at this stage. |
| [`OP_PARAM_ARG_INDEX`](../codegen/subgraph.py) | `layer_norm` | **Explicit** | Lists the twin at the same argument index; `weight` remains argument 2. |
| [`_vector_op_tiling_limits`](../codegen/transform/tiling/search.py) guard | `softmax`, `layer_norm` | `layer_norm`: **Explicit**; `softmax`: **Phase-safe** | Lists the `layer_norm` twin; `softmax` remains ATen at this stage. |
| [`_vector_op_tiling_limits`](../codegen/transform/tiling/search.py) constraint branch | `softmax`, `layer_norm` | `layer_norm`: **Explicit**; `softmax`: **Phase-safe** | The `layer_norm` twin uses `last_dim = -len(normalized_shape)`; `softmax` remains ATen. |
| [`_REDUCTION_SCRATCH`](../codegen/node_info.py) | `softmax`, `layer_norm` | `layer_norm`: **Explicit**; `softmax`: **Phase-safe** | Includes the `layer_norm` self-entry; a `softmax` twin does not normally reach this table. |
| [`_REDUCTION_POINTWISE_OPS`](../codegen/transform/bufferize/bufferization.py) | `softmax`, `layer_norm` | `layer_norm`: **Explicit**; `softmax`: **Phase-safe** | Lists the `layer_norm` twin; `softmax` remains ATen before generic retargeting. |
| [`pad_vector_op_dimensions`](../codegen/transform/padding.py) dispatch | `softmax`, `layer_norm` | `layer_norm`: **ATen-only by design**; `softmax`: **Phase-safe** | Matching the `layer_norm` twin would pad an already-padded operator again; a `softmax` twin does not yet exist. |
| [`is_compute_op`](../codegen/aten_classifier.py) | `softmax`, `layer_norm` | **Explicit** | The hand-maintained `_QUANTIZED_COMPUTE_OPS` allowlist includes both twin names. |
| [`_reduced_dims`](../codegen/node_info.py) | `softmax` | **Phase-safe** | It is reached through `reduction_scratch` before generic retargeting. A twin here would misread `dim` as `normalized_shape`. |
| [`rewrites.py`](../codegen/transform/rewrites.py) and [`xnnpack_quantizer_utils.py`](../quantization/quantizer/xnnpack_quantizer_utils.py) | `softmax`, `layer_norm` | **Phase-safe** | These passes run before scratch-aware twins are introduced. |

The generated ATen section of `aten_classifier.py` can be refreshed with
[`tools/gen_aten_classifier.py`](../../../tools/gen_aten_classifier.py). The
`quantized_ops` allowlists below that section are maintained by hand.

## Adding a New Lookup

Before adding a lookup keyed by `node.target`, determine whether it runs:

1. before vector padding;
2. between vector padding and bufferization;
3. inside a standard bufferized kernel; or
4. inside a specialized bufferization path.

Then list every target that can reach that stage. When practical, normalize
reduction targets through `reduction_op` before performing the lookup.
